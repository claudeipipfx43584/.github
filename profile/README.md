<p>白名单这件事，很多人以为是一个开关：填上自己的 IP，保存，完事。实际上一套代理线路能被约束的位置至少有六处，白名单只是其中最表面的一处。哪一处生效、优先顺序怎么排、成员权限能不能覆盖全局设置，这些细节决定了你配完之后到底是"只有我能用"还是"谁拿到账密都能用"。这篇按参数说明书的写法，把每一项的取值、默认行为和影响讲清楚，最后给三套可以直接照抄的配置。</p>

<h2>一、参数总表：一条线路能被约束的六个位置</h2>
<p>把线路拆开看，能挂约束的地方是：接入鉴权、来源 IP 白名单、目标出口绑定、并发与连接数、流量与时长额度、成员与子账号权限。前两项决定"谁能连进来"，第三项决定"连进来之后从哪出去"，后三项决定"能用多少、能干什么"。配置顺序建议从上往下，先定鉴权再谈额度，否则额度是给未知用户设的。</p>

<h2>二、鉴权参数：账密、白名单、Token 各自管什么</h2>
<p>账密鉴权是基础项，格式一般是 用户名:密码@网关地址:端口，优点是什么客户端都支持，缺点是密码一旦进了截图、日志、聊天记录就等于公开。白名单鉴权是把来源 IP 写进服务端的允许列表，只有列表里的地址能建立连接，密码可以留空或者设成固定值。Token 鉴权多见于支持 HTTP 头的服务，把一串密钥放在 Proxy-Authorization 里，好处是能按 Token 吊销，不用改所有人的密码。</p>
<h3>三种鉴权的组合方式</h3>
<p>比较稳的做法是白名单加账密双开：来源 IP 不在白名单直接拒绝，在白名单里还要过账密。这样即使密码泄露，别人从自己的网络也连不进来。Token 适合程序调用场景，比如 CI 里跑脚本需要临时出口，发一个有效期 24 小时的 Token，用完即废，比共享一个长期密码安全得多。</p>
<h3>白名单的粒度怎么选</h3>
<p>家用宽带写单个 /32 就行，注意运营商动态分配会变，变了要重填。办公室有多条出口，写 /29 或直接把三条固定 IP 都列上。云主机场景写内网出口的 NAT 地址，不要写实例的内网 IP，那个地址对服务端不可见。写完立刻验证：从白名单外的网络 curl 一次，应该直接连不上；从白名单内再 curl 一次，应该通。这一步别省，很多人配完发现"没生效"，其实是客户端走了系统代理绕过了。</p>

<h2>三、IP 绑定参数：绑定入口、绑定出口、绑定并发</h2>
<p>"IP 绑定"这个词在不同服务商那里指三件不同的事，配之前一定要问清楚是哪一种。第一种是绑定你的来源 IP，等价于白名单；第二种是绑定出口 IP，让某个账号固定从某个地址出去；第三种是绑定并发，把某个 IP 的同时连接数锁死。三者名字一样，作用完全不同，混了就会出现"我明明绑了 IP，为什么出口还在变"。</p>
<h3>出口绑定的两种实现</h3>
<p>按会话粘滞（sticky session）是靠一个会话标识维持出口，通常给一个 5 到 30 分钟的窗口，窗口内同一标识走同一 IP；固定 IP 绑定是把这个账号永久映射到一个地址，除非手动解绑。前者便宜、灵活，适合抓取类任务；后者贵，适合长期账号，因为出口稳定本身就是价值。</p>
<h3>并发参数怎么填</h3>
<p>一个浏览器标签页在长对话场景下可能维持 4 到 6 条连接，多开几个标签很容易上到 20。如果套餐并发只有 10，表现出来就是页面加载一半卡住、流式输出中断。建议按"账号数×5"估并发下限，再留 30% 余量。命令侧可以用 curl 并发跑十个请求压一下：for i in $(seq 10); do curl -s -o /dev/null -w "%{http_code} " --proxy 你的代理 https://ipinfo.io/ip & done; wait，看有没有超时。</p>

<h2>四、成员与权限参数：子账号、可用线路、流量上限</h2>
<p>团队场景下最容易被忽略的是权限设计。常见的坑是所有人共用一个主账号密码，谁改了配置没人知道，谁用超了流量也查不出来。正常的做法是给每个人开子账号，权限分三档：只读能看用量和账单，可用能连线路但改不了配置，管理能增删线路和成员。子账号再挂独立的流量上限，超额自动停，不影响别人。</p>
<h3>按项目切线路还是按人切</h3>
<p>人少按人切，人多按项目切。按人切的好处是责任清晰，账单直接对应到人；按项目切的好处是人员流动时不用重新分配。两者可以叠加：线路按项目建，成员按项目授权，个人只拿到自己项目的线路权限。</p>
<h3>审计日志要看哪几列</h3>
<p>至少要能看到：时间、成员、线路、来源 IP、用量。有这五列，出了问题能定位到人、定位到时间点。没有日志的服务商，团队场景基本不用考虑，出问题只能靠猜。</p>

<h2>五、参数怎么填：三套典型配置</h2>
<p>第一套是单人自用：白名单写家里和公司的两个固定 IP，账密加白名单双开，出口固定一个独享静态住宅，并发 20，流量按 100GB/月。这套配置月成本在几十到一百多元区间，仅供参考。</p>
<p>第二套是小团队五个人：主账号管线路，五个子账号各挂一条独享出口，权限设为"可用"，流量各 50GB，超额停用。白名单写办公室出口段加各人家庭 IP 共七个条目。这套的关键是子账号之间互相看不到用量，只有管理员能看全量。</p>

<h2>常见问答</h2>
<h3>白名单加了 IP，为什么还是能从不认识的网络连上？</h3>
<p>答：多半是配置只加在了控制台的"允许列表"里，但线路本身还开着账密直连。检查线路详情里的鉴权模式是否切换成"白名单优先"，再从一个陌生网络实测一次。</p>
<h3>动态公网 IP 天天变，白名单没法用怎么办？</h3>
<p>答：两个办法。一是让路由器跑一个定时脚本，IP 变了自动调服务商 API 更新白名单；二是改用 Token 鉴权加短有效期，牺牲一点安全性换维护成本。</p>
<h3>出口绑定之后，为什么 ipinfo 显示的城市还是变？</h3>
<p>答：出口 IP 没变但 IP 库的城市数据可能有多套，不同查询源结论不同。以 ipinfo 与 ip-api 同时查一次为准，两者都变才说明出口真的换了。</p>
<h3>子账号能不能只看用量不给连接权限？</h3>
<p>答：多数服务商支持"只读"角色，能看账单和用量但不能建连接。给财务或负责人开这个角色比较合适，避免为了看账单独共享主密码。</p>

<h2>合规提示</h2>
<p>本文描述的是代理线路自身的鉴权与权限配置方法，目的是提升账号与资源的安全性，不涉及绕过任何平台规则。选择服务商时应确认其具备合法经营资质，并在合同中明确线路用途与责任边界。</p>
<p>白名单、Token 等凭据属于敏感信息，应通过密钥管理工具分发，不要写进代码仓库或聊天记录。团队内部也应约定离职人员的权限回收流程。</p>
<p>文中参数取值与价格均为经验区间，不同服务商的控制台用词可能不同，仅供参考，以实际产品文档为准。</p>
